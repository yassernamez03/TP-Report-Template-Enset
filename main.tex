\section{Introduction}

Dans ce laboratoire, l'objectif est de cr\'eer et configurer un serveur Linux dans le cloud afin de comprendre les bases de l'administration syst\`eme \`a distance. Pour cela, nous avons utilis\'e la plateforme \textbf{Amazon Web Services (AWS)}, et plus pr\'ecis\'ement le service \textbf{Amazon EC2}, pour d\'eployer une instance Ubuntu 22.04 LTS.

L'outil central de ce lab est \textbf{Webmin}, une interface web d'administration syst\`eme pour Linux. Gr\^ace \`a lui, il est possible de g\'erer un serveur complet — utilisateurs, services, firewall, configuration r\'eseau, SSH, Cron, etc. — depuis un simple navigateur, sans recourir syst\'ematiquement au terminal.

Ce rapport pr\'esente les diff\'erentes \'etapes r\'ealis\'ees : la cr\'eation de l'instance EC2, la connexion SSH au serveur, l'installation et la configuration de Webmin, les tests fonctionnels effectu\'es sur les modules cl\'es, ainsi que la s\'ecurisation simple du serveur.

\subsection*{Outils et technologies utilis\'es}

\begin{itemize}
  \item \textbf{Amazon EC2} : service AWS permettant de cr\'eer et g\'erer des serveurs virtuels dans le cloud.
  \item \textbf{Ubuntu Server 22.04 LTS} : syst\`eme d'exploitation install\'e sur l'instance.
  \item \textbf{Webmin} : interface web d'administration Linux (utilisateurs, services, firewall, SSH, Cron\ldots).
  \item \textbf{Git Bash / Terminal SSH} : outil de connexion au serveur depuis Windows.
  \item \textbf{Navigateur web} : acc\`es \`a l'interface Webmin via HTTPS sur le port 10000.
\end{itemize}

\subsection{\'Etape 2 — Connexion au serveur via SSH}

Apr\`es le lancement de l'instance, la connexion au serveur se fait via SSH en utilisant la cl\'e priv\'ee g\'en\'er\'ee.

\begin{commandbox}
\begin{lstlisting}
# Restriction des permissions de la cle privee (obligatoire sous Linux/macOS)
chmod 400 Webmin.pem

# Connexion SSH a l'instance EC2
ssh -i "Webmin.pem" ubuntu@<IP-PUBLIQUE>
\end{lstlisting}
\end{commandbox}

\end{resultatbox}

\subsection{\'Etape 3 — Installation de Webmin}

L'installation de Webmin se d\'eroule en plusieurs sous-\'etapes.

\subsubsection*{1. Mise \`a jour du syst\`eme}

\begin{commandbox}
\begin{lstlisting}

\begin{commandbox}

\end{commandbox}

\begin{figure}[H]

\subsubsection*{3. Ajout du d\'ep\^ot Webmin}

Le d\'ep\^ot officiel Webmin utilise une signature DSA non support\'ee par les versions r\'ecentes d'APT ; on utilise donc l'option \texttt{trusted=yes}.

\begin{commandbox}
\begin{lstlisting}
echo "deb [trusted=yes] https://download.webmin.com/download/repository sarge contrib" \
  | sudo tee /etc/apt/sources.list.d/webmin.list

sudo apt update
\end{lstlisting}
\end{commandbox}

\begin{figure}[H]

\subsubsection*{4. Installation de Webmin}

\begin{commandbox}
\begin{lstlisting}

\end{lstlisting}
\end{commandbox}

\subsection{\'Etape 5 — Acc\`es \`a l'interface Webmin}

Webmin \'ecoute sur le port \textbf{10000} en HTTPS. Pour y acc\'eder :

\begin{enumerate}
  \item Ouvrir un navigateur et saisir l'URL : \texttt{https://<IP-PUBLIQUE>:10000}
  \item Accepter le certificat SSL auto-sign\'e (avertissement de s\'ecurit\'e normal).
  \item Se connecter avec les identifiants du syst\`eme (utilisateur \texttt{ubuntu} ou \texttt{root}).
\end{enumerate}

Si n\'ecessaire, d\'efinir un mot de passe root :

\begin{commandbox}
\begin{lstlisting}
sudo passwd root
\end{lstlisting}
\end{commandbox}

\subsubsection*{6.5 Configuration SSH}

\textbf{Chemin :} \textit{Modules $\rightarrow$ Servers $\rightarrow$ SSH Server}

Les param\`etres SSH suivants ont \'et\'e modifi\'es :
\begin{itemize}
  \item \textbf{Port SSH} : modifi\'e vers le port \texttt{2222} pour r\'eduire l'exposition aux scans automatiques.
  \item \textbf{Nombre de tentatives de connexion} : limit\'e (MaxAuthTries = 3).
  \item \textbf{Authentification par mot de passe} : activ\'ee.
  \item \textbf{Connexion root} : configur\'ee pour l'interdire (\texttt{PermitRootLogin no}).
\end{itemize}

\begin{enumerate}

  \item \textbf{Erreurs de d\'ep\^ot Webmin (signature DSA)} \\
  Le d\'ep\^ot Webmin utilise une signature DSA non support\'ee par APT moderne, g\'en\'erant une erreur lors du \texttt{apt update}. \\
  \textit{Solution :} utilisation de l'option \texttt{trusted=yes} dans la d\'eclaration du d\'ep\^ot.

  \item \textbf{Connexion SSH et permissions de la cl\'e \texttt{.pem}} \\
  SSH refuse les cl\'es priv\'ees trop permissives (erreur \textit{Permissions 0644 are too open}). \\
  \textit{Solution :} appliquer \texttt{chmod 400 Webmin.pem} avant toute connexion.

  \item \textbf{Connexion \`a Webmin et mot de passe} \\
  L'interface Webmin utilise les comptes syst\`eme Linux. En cas de mot de passe root inconnu, la commande \texttt{sudo passwd root} permet de le red\'efinir.

  \item \textbf{Certificat SSL auto-sign\'e} \\
  Le navigateur affiche un avertissement de s\'ecurit\'e (\textit{Your connection is not private}). \\
  \textit{Solution :} accepter manuellement le certificat en cliquant sur \textit{Avanced $\rightarrow$ Proceed}.

  \item \textbf{Mauvaise configuration du pare-feu UFW} \\
  Une activation d'UFW sans pr\'ealablement autoriser les ports 22 et 10000 coupe l'acc\`es SSH et Webmin. \\
  \textit{Solution :} toujours ex\'ecuter \texttt{ufw allow 22} et \texttt{ufw allow 10000} avant \texttt{ufw enable}.

  \item \textbf{Modification du port SSH} \\
  Apr\`es avoir chang\'e le port SSH depuis Webmin, la prochaine connexion SSH doit sp\'ecifier le nouveau port avec \texttt{ssh -p <nouveau\_port>}, sinon la connexion \'echoue.

\end{enumerate}

\section{Conclusion}

Ce laboratoire a permis d'acqu\'erir une exp\'erience concr\`ete de l'administration d'un serveur Linux dans le cloud, depuis le d\'eploiement jusqu'\`a la s\'ecurisation, en passant par la gestion des ressources syst\`eme.

\textbf{Comp\'etences acquises :}
\begin{itemize}
  \item D\'eploiement d'une instance EC2 sur AWS avec configuration r\'eseau ad\'equate.
  \item Installation et configuration de Webmin sur Ubuntu Server.
  \item Administration graphique d'un serveur Linux (utilisateurs, services, fichiers, cron).
  \item Mise en place d'une s\'ecurit\'e de base : pare-feu UFW, restriction SSH, HTTPS.
\end{itemize}

\textbf{Points importants \`a retenir :}
\begin{itemize}
  \item Webmin simplifie consid\'erablement l'administration syst\`eme, mais une bonne compr\'ehension des commandes Linux sous-jacentes reste indispensable pour diagnostiquer les probl\`emes.
  \item La s\'ecurit\'e d'un serveur cloud n\'ecessite une approche multicouche : groupe de s\'ecurit\'e AWS, pare-feu syst\`eme (UFW), et configuration applicative (SSH, HTTPS).
  \item La gestion des cl\'es SSH et des permissions de fichiers est cruciale pour \'eviter les \'echecs de connexion.
\end{itemize}

\textbf{Perspectives d'am\'elioration :}
\begin{itemize}
  \item Approfondir la configuration du serveur web Apache ou Nginx via Webmin.
  \item Mettre en place un certificat SSL valide (Let's Encrypt) pour remplacer le certificat auto-sign\'e.
  \item Configurer des r\`egles de firewall plus complexes et des alertes de monitoring.
  \item Explorer les modules avanc\'es de Webmin (Samba, Bind DNS, etc.).
\end{itemize}
